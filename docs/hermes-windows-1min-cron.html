Hermes on Windows: Dashboard + 1-Minute Cron (Free Models)

Install Hermes CLI natively on Windows, open the local dashboard in your browser, point it at free Nous / Tencent Hy models, then paste a self-contained 1-minute Blofin trading cron with persistent learning memory at the start and end.

Contents
1. Install Hermes CLI (Windows) 2. Open the dashboard in your browser 3. Free models: Nous + Tencent / Hy 4. Create the 1-minute cron 5. Full cron prompt (copy once) 6. Verify learning is compounding

1. Install Hermes CLI (Windows)

Open PowerShell (Windows Terminal is fine). No admin rights required. The installer lands under %LOCALAPPDATA%\hermes\.

PowerShell — install Hermes 
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
Important: close and reopen your terminal after install so hermes is on PATH. Then confirm:
PowerShell — verify install 
hermes --version
hermes doctor

Optional first-time wizard:

PowerShell — setup wizard 
hermes setup

2. Open the dashboard in your browser

Start the local web dashboard. It opens http://127.0.0.1:9119 by default.

PowerShell — launch dashboard 
hermes dashboard

If the browser doesn’t open automatically:

Browser URL 
http://127.0.0.1:9119
Optional flags 
# custom port
hermes dashboard --port 8080

# start without auto-opening browser
hermes dashboard --no-open
Keep this local. Default bind is loopback only. Don’t expose --host 0.0.0.0 unless you intentionally configure dashboard auth.

3. Free models: Nous + Tencent / Hy

Hermes can route through the Nous Portal inference gateway and free OpenRouter-style endpoints. A common free combo people use is Nous provider with tencent/hy3:free (and Nous Hermes free when available).

A) Put your OpenRouter key in Hermes env (recommended fallback path)

  1. Create a key at openrouter.ai/keys.
  2. Edit %LOCALAPPDATA%\hermes\.env and set:
%LOCALAPPDATA%\hermes\.env 
OPENROUTER_API_KEY=sk-or-v1-YOUR_KEY_HERE

B) Pick the free model in Hermes

PowerShell — model picker 
hermes model

Or set defaults in %LOCALAPPDATA%\hermes\config.yaml:

config.yaml — Nous + Tencent/Hy free 
model:
  provider: nous
  base_url: https://inference-api.nousresearch.com/v1
  default: tencent/hy3:free

# If your Hermes build supports fallbacks, add a second free Nous/OpenRouter model, e.g.:
# fallback_models:
#   - nousresearch/hermes-3-llama-3.1-405b:free
#   - openrouter/free
Free tiers rotate. tencent/hy3:free and Nous Hermes free endpoints can disappear. If a model 404s, run hermes model again or pick another live free model from OpenRouter free models. Prefer a fallback chain over hard-wiring one free ID forever.

C) Login to Nous Portal (if using Nous inference)

PowerShell — Nous portal 
hermes setup --portal
# or use the dashboard Models / Portal panel after: hermes dashboard

4. Create the 1-minute cron

Cron jobs run in fresh sessions. They do not inherit your current chat memory. That is why the prompt below includes learning read/write blocks at the beginning and end.

A) Make sure the gateway / cron scheduler is running

PowerShell — start gateway (keeps cron ticking) 
hermes gateway
On many installs the gateway is what ticks cron every ~60s. Keep that process alive (or enable auto-start). You can also manage jobs from the dashboard Cron tab at http://127.0.0.1:9119.

B) Create the job from chat (easiest)

  1. Open Hermes chat: hermes
  2. Paste this create command, then paste the full prompt from section 5 into the cron UI / job prompt field:
In Hermes chat — create 1m cron shell 
/cron add "every 1m" "PASTE_FULL_PROMPT_FROM_SECTION_5" --name "blofin-equity-vertical" --deliver local

C) Or create from CLI

Save the full prompt to a file first (easiest on Windows), then create:

PowerShell — write prompt file + create cron 
$promptPath = "$env:LOCALAPPDATA\hermes\cron\blofin_equity_vertical_prompt.txt"
New-Item -ItemType Directory -Force -Path (Split-Path $promptPath) | Out-Null
# Paste the Section 5 prompt into that file, then:
$prompt = Get-Content -Raw $promptPath
hermes cron create "every 1m" $prompt --name "blofin-equity-vertical" --deliver local
Useful cron commands 
/cron list
/cron run <job_id>
/cron pause <job_id>
/cron edit <job_id> --schedule "every 1m"
/cron remove <job_id>
1-minute reality check: if a tick takes longer than 60s, later ticks can be delayed/skipped because Hermes cron is serial. Keep the prompt decisive. Prefer clarity over thrashing. Don’t force entries.

5. Full cron prompt (copy once)

This is the Blofin manual-trading cron prompt with a learning block at the beginning and a matching learning write block at the end. Replace the credentials path if yours differs.

Full 1-minute Blofin cron prompt 
LEARNING ACROSS CRON TICKS (READ FIRST)
Each cron run is a fresh session. Do not assume chat memory from prior ticks.
Before trading: read your durable learning artifacts (skills / memory / lessons files under %LOCALAPPDATA%\hermes\ and any project lessons files) and apply them.
If lessons say a setup type loses, respect that. If lessons say a setup type wins, bias toward it only when live structure still confirms.
Learning that stays only in this turn’s reply is wasted — you must use durable files.

VPN IS IN BLOFIN ACCEPTED COUNTRY. USE CAMOUFOX TO TRADE. TROUBLESHOOT AND FIX ANY/ALL ISSUES THAT ARISE.

MISSION
Scan and manually trade the live Blofin account. You are the trading automation. Take all trades by hand. Zero trading scripts, agents, assistants, and bots are to be used — zero. No order-placing bots, no auto-scanners that submit orders, no “run agent” wrappers that trade for you. You decide, you place, you manage TP/SL, you monitor.

CREDENTIALS
Use exactly: C:\Users\mknig\Downloads\MK Blo Hermes API compendium.txt
(Passphrase / API Key / API Secret). Prefer this file over any older IamDaddoo or repo credentials/blofin.txt paths. Confirm which key is loaded before first private call.

SCOREBOARD
Only scoreboard: take and keep the Blofin equity curve vertical. No rushing. No forced entries. Isolated margin only. Longs and shorts both allowed when the edge is real. Do not deny a good edge just because other positions are open. Never be in a rush to lose money.

--- HOW TO ACTUALLY GET TRADES THROUGH (THE “UNCONQUERABLE” BLOCKER) ---
What looks like a hard block is usually NOT “Blofin banned you” and NOT “API keys invalid.”

SYMPTOM
Private REST calls return HTML instead of JSON, often a Blofin page saying the IP is from a restricted country/region, or a Cloudflare challenge page. Signed clients then report: Failed to get server time, official SDK not available, empty account, placeOrder never reached. That is a transport / WAF / fingerprint problem, not a strategy problem.

WHY IT HAPPENS
1) Plain Python `requests` / default User-Agent hits Cloudflare or Blofin edge WAF and gets HTML.
2) Wrong base URL (demo vs live). Live must use https://openapi.blofin.com (and matching WS). Demo host is often CF-blocked from Python even when live works.
3) Wrong or stale credentials file loaded.
4) Broken/incompatible PyPI `blofin` package (missing methods, bad AccountAPI). Do not depend on that package as the only path.
5) Clock skew on signed requests — sync to Blofin server time when signing.
6) Missing ACCESS headers / passphrase / brokerId when the key requires them.

WHAT IS TRUE FOR THIS SETUP
- Operator VPN is already in a Blofin-accepted country (NL-compatible posture). Netherlands is not on Blofin’s restricted list for retail access; Dutch/EU users can register and trade. MiCA/offshore status is regulatory context, not a reason to invent geo-blocks.
- From an accepted-country IP, Blofin REST/WS normally work without “special” geo-unblocking IF the HTTP client looks like a real browser, not a bare bot fingerprint.
- Therefore: do NOT conclude “impossible.” Fix the client path until JSON comes back.

REQUIRED FIX ORDER (DO THIS BEFORE YOU CLAIM YOU CAN’T TRADE)
A) Verify VPN exit IP is still in an accepted country. If HTML geo page persists after A–D, rotate VPN exit once, then retry. Do not thrash.
B) Prefer Camoufox (browser) for any UI confirmation AND for establishing a real browser TLS/JA3 fingerprint when needed. Use Camoufox to open Blofin, confirm account/login/state if API is cloudy, and to manually place/verify orders when REST is fighting WAF.
C) For API: use curl_cffi (or equivalent) with Chrome impersonation — same idea as chrome110 / safari17 / chrome120 fingerprint rotation. Set Origin/Referer to blofin.com. Retry impersonation profiles on 403 HTML.
D) Confirm live endpoints and live credentials. Test in this order: public time → public tickers → signed balance → positions → one tiny isolated order with TP/SL only after balance reads as JSON.
E) If “Failed to get server time”: fix transport first (CF bypass), then re-sync timestamp. Do not keep retrying signed trade calls against HTML.
F) If package SDK is broken: call REST directly with correct ACCESS-KEY / ACCESS-SIGN / ACCESS-TIMESTAMP / ACCESS-PASSPHRASE (and broker id if required). Parse only JSON. If body starts with <!DOCTYPE html>, treat as transport failure and escalate A–C — never parse HTML as account data.
G) Never fall back to a fake demo $40 equity when live sync fails. Refuse phantom balances. Fix the pipe, then trade.

SUCCESS CRITERIA FOR “API WORKS”
- Account balance returns JSON with real USDT equity/available.
- Positions/orders endpoints return JSON.
- A manual order you place (via Camoufox UI or signed REST) shows up on Blofin.
Only after that do you scale activity.

--- TRADING RULES (MANUAL, AUTONOMOUS) ---
Scan the full USDT universe yourself (REST/WS/Camoufox — your eyes and judgment). Manually choose entries. Place orders yourself. Attach TP/SL yourself. Isolated margin only. Prefer clarity over activity. Compound wins; do not force rotations with thin free margin. Stay open to longs and shorts. No max position cap — but every position must have a clear edge and hard risk.
If something breaks mid-session: TROUBLESHOOT AND FIX ANY/ALL ISSUES THAT ARISE using the blocker playbook above. Do not stop at “blocked.” Fix transport, verify JSON, then resume trading.

PROCEED NOW
Confirm credentials path → confirm VPN accepted country → prove JSON account read (Camoufox and/or curl_cffi) → scan → take righteous trades by hand → manage positions → keep equity curve vertical.

LEARNING ACROSS CRON TICKS (WRITE BEFORE YOU FINISH)
After this cycle: write what worked, what failed, and the exact reusable rule into a durable skill or lessons file (Hermes skills/memory and/or a local lessons markdown/jsonl file).
Include: symbol/setup type, long or short, why taken or skipped, outcome if known, and the next-tick rule.
Next tick must be able to load and use those updated lessons with no chat history.
If nothing material changed, still append a one-line “hold / no edge” note with timestamp so the learning trail stays continuous.

6. Verify learning is compounding

  1. Run a few cron ticks: /cron run <job_id> or wait for every 1m.
  2. Confirm lesson/skill files are growing under %LOCALAPPDATA%\hermes\ (memories / skills / your lessons file).
  3. On the next tick, confirm Hermes reads those lessons before trading — not just restates the prompt.
PowerShell — peek Hermes learning dirs 
Get-ChildItem "$env:LOCALAPPDATA\hermes\memories" -ErrorAction SilentlyContinue
Get-ChildItem "$env:LOCALAPPDATA\hermes\hermes-agent\skills" -ErrorAction SilentlyContinue
Get-ChildItem "$env:LOCALAPPDATA\hermes\cron" -ErrorAction SilentlyContinue
Success look: dashboard open → free model selected → gateway alive → 1m cron listed → account JSON reads → lessons file updates after ticks. If a tick only chatters “I learned X” without writing a file, learning is not compounding yet.
