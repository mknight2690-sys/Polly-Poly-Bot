Set your computer to never sleep, and make sure your internet stays on

If the computer sleeps, Hermes stops for that time. If the internet drops, Hermes can’t reach Coinbase.

Windows
Mac

Click path:

  • Click Start, then type Power and sleep or Power & battery.
  • Set Turn off my screen after to Never when plugged in.
  • Set Put my device to sleep after to Never when plugged in.
  • Optional: Start → type Choose what closing the lid does → set When I close the lid to Do nothing while plugged in.
powercfg /change standby-timeout-ac 0
powercfg /change standby-timeout-dc 0
powercfg /change monitor-timeout-ac 0
powercfg /change monitor-timeout-dc 0
powercfg /change hibernate-timeout-ac 0
powercfg /change hibernate-timeout-dc 0

Click path:

  • Click the Apple menu () → System Settings.
  • Open Lock Screen or Battery / Energy Saver.
  • Set display sleep to Never on power adapter while you are learning.
  • Keep the MacBook lid open while Hermes runs, if you can.

Sign up for a Coinbase account

Coinbase is where your money and your account live in this setup.

Copy this link and paste it into your browser address bar

https://www.coinbase.com

Then press Enter. If you already have a Coinbase account, you can skip to sign-in and move on.

  • Use a real email and a password you will remember.
  • Verify your email and phone when Coinbase asks.
  • Complete the identity check if Coinbase asks for a photo ID. That is normal.

Put money into Coinbase

A good first buy

On Coinbase, choose Buy or Trade, pick the crypto Coinbase is offering you for a first purchase, and use the payment method Coinbase shows you.

Watch the fee preview

Coinbase shows you a fee preview before you confirm. Take a look at it. It is normal for a first buy to have a fee.

Set up the 10-minute cron job

This is the heartbeat of the setup. You create a repeating job in the Hermes dashboard and give it the Coinbase prompt from the file you have. This tutorial sets it to run every 10 minutes.

What to do in the dashboard

  • Open the Cron section, or the section the dashboard calls Jobs / Scheduled.
  • Create a new scheduled job.
  • Schedule: every 10 minutes.
  • Name: coinbase-equity-vertical
  • Provider: Nous
  • Model: tencent/hy free
  • Paste the prompt from the next part into the prompt box, then save.

The cron prompt

=== COINBASE PERPETUALS — 10-MIN AUTONOMOUS TRADING CRON ===

UNIVERSE (read this once, act on it)
There are at least 160 Coinbase perpetual futures. They are NOT found by guessing symbols — they are enumerated from the correct endpoint with the right product filter. The "right spot" is:
  GET https://api.coinbase.com/api/v3/brokerage/products?product_type=PERPETUAL
If that returns an empty/short perp list (US-retail restriction), the perps actually live on Coinbase International Exchange — switch host to:
  https://api.international.coinbase.com  (same /api/v3/brokerage/... path, product_type=PERPETUAL)
Do NOT stop until you have enumerated the full perpetual list (target >=160). A short list means wrong host/filter, not "they don't exist."

DEMO / MENTAL-TRADE MANDATE (always on, even while trading real money)
Take mental trades on the perpetual futures you'd trade/want to follow, and follow those imaginary trades to completion, so you learn whether your methodology was right — as if you traded real money. This builds conviction and removes "what-ifs." Log each mental trade (entry/TP/SL/R:R + trigger) in the lessons file so later ticks can mark it TP/SL-hit and you learn from it.

LEARNING ACROSS CRON TICKS (mandatory loop)
Each cron run is a fresh session. Before trading: read your durable lessons file and apply it. After each cycle: append what worked, what failed, and the exact rule to reuse. Next tick MUST load and use those updated lessons. Learning that stays only in this reply is wasted.
Lessons file (create if missing): C:\Users\mknig\AppData\Roaming\knight-trader\hermes\lessons\coinbase_perps_trading.md

MISSION
Scan and manually trade the live Coinbase perpetual universe. YOU are the trading automation: you decide, you place, you attach TP/SL, you monitor. Zero external order-bots, zero auto-scanners that submit orders, zero "run-agent" wrappers. Your own reasoning places every order.

CREDENTIALS
Use exactly: C:\Users\mknig\OneDrive\Documents\Coinbase MK API Keys.txt
Confirm which key type is loaded BEFORE the first private call:
  • MODERN Coinbase Cloud API key = "Key Name" + "Private Key" (a PEM, usually -----BEGIN EC PRIVATE KEY-----). There is NO passphrase.
  • LEGACY key = API key + secret + passphrase (old Pro style; perps are NOT on this API).
If the file has a passphrase line, it is legacy — do not use it for perps; get a Cloud API key.

SCOREBOARD
Keep the Coinbase equity curve vertical. No rushing. No forced entries. Isolated margin. Leverage only within account tier / per-instrument max (default cap 10x, smaller if thin). Take longs AND shorts when the edge is real. Do not deny a good edge just because other positions are open. Never be in a rush to lose money.

--- HOW TO ACTUALLY GET TRADES THROUGH (COINBASE API BLOCKERS) ---
Symptom: 401/403, HTML error pages, "invalid signature", "timestamp expired", or empty/blocked responses. That is an auth/transport/clock problem, NOT "Coinbase banned you" and NOT invalid keys.
Why it happens:
  1) Wrong auth for the endpoint: modern Cloud key needs an ES256 JWT (see below); legacy needs CB-ACCESS-* HMAC headers. Mixing them = 401.
  2) Clock skew: Coinbase tolerates <30s drift. Sync NTP first.
  3) PEM private-key formatting: Python must load the key WITH its newlines intact. Stripped `\n` = invalid signature.
  4) Rate limits: Advance/Brokerage enforces strict req/s. Batch reads, sleep between signed calls.
  5) Wrong host/base: Live = https://api.coinbase.com/api/v3/brokerage/ (Advance) or https://api.international.coinbase.com (Coinbase International perps). Not deprecated Pro/Legacy hosts.
What is true here: with correct signing + synced clock + correct host, REST/WS returns clean JSON. Do NOT conclude "impossible" — fix the signing path until JSON comes back.
REQUIRED FIX ORDER:
  A) Sync clock (NTP). Verify connectivity.
  B) Load creds; detect key type (Cloud PEM vs Legacy).
  C) Prove step-by-step: (1) GET .../brokerage/time  (2) GET .../brokerage/products?product_type=PERPETUAL  (3) SIGNED GET .../brokerage/accounts (balances)  (4) positions/orders.
  D) MODERN CLOUD KEY SIGNING (recommended): build an ES256 JWT — header {alg:ES256, typ:JWT, kid:}; claims {iss:"cdp", sub:, uri:" ?", nbf, iat, exp(now+120)}; sign with the EC private key. Send header `Authorization: Bearer `. Easiest/safest: use the official `coinbase` / `cdp-sdk` Python package which handles JWT + PEM for you.
  E) If 401: re-check PEM newlines + clock + that `uri` claim matches method+path+query exactly (lowercase host, no trailing slash).
  F) Parse strictly JSON. HTML/non-JSON body = transport error → fix host/auth/base URL.
  G) Never fall back to a fake demo balance. Refuse phantom numbers. Fix the pipe, then trade.
SUCCESS CRITERIA ("API works"):
  • Balances endpoint returns JSON with real USD/USDT equity + available.
  • Product/ticker/order-history return valid JSON.
  • A manual order you place (API or Coinbase UI) shows in account state with attached TP/SL.
Only then scale activity.

--- TRADING STRATEGY (YOUR EDGE — apply every tick) ---
Scan the FULL perp universe each tick for candidate flags; deep-dive the liquid top ~40 by 24h volume with this multi-timeframe gate (1m→5m/15m/1h resample). Take a trade ONLY when a gate FULLY fires; otherwise HOLD.
  LONG mean-reversion: 1h RSI < 32  AND  price >1.2 ATR below 1h EMA20  AND  5m candle bull_body (close>open)  AND  5m RSI turning up  AND  5m volume ratio > 1.3x  AND  live R:R >= 2 (TP = 1h EMA20, SL = below 5m swing low). Compute R:R in ONE snapshot — if it is <2 the bounce already happened, do NOT chase.
  SHORT continuation: 15m TRUE stepped lower-high (not just red candles)  AND  15m RSI 40–65  AND  15m volume ratio > 1.3x  AND  R:R >= 2 confirmable to a real support.
  BREAKOUT-long: only a 5m CLOSE holding above the 20-period 5m high on sustained volume >1.4x with R:R >= 2. REJECT wick-only / snap-back / volume-collapse fakeouts.
HARD REJECTS (documented traps): high-volume drops with no 5m bull turn = CAPITULATION FLUSH (don't catch the knife); micro-cap pumps (>15% on thin vol) = manipulation; selling into deep oversold bottoms where R:R < 2. If NO gate fires → HOLD. Forcing = losing money.
SIZING: isolated margin, risk <= ~1–1.5 USDT-equivalent margin per trade at this account size; min notional per instrument respected; attach TP/SL at placement, never a standalone "stop" ordertype if the API lacks it (verify TP/SL exists via a follow-up query).

RULES (MANUAL, AUTONOMOUS)
Scan EVERY universe asset with your own judgment. Choose entries, place orders, attach TP/SL, monitor. Prefer clarity over activity; compound wins; do not force rotations on thin capital. If something breaks mid-session: troubleshoot per the blocker playbook, verify JSON, resume. Do not stop at "blocked."

PROCEED NOW
Confirm credentials path → detect key type → prove JSON balance read (sync clock, JWT/PEM) → enumerate the >=160 perps → scan universe → take righteous trades by hand when a gate fires (else HOLD) → manage/monitor positions + TP/SL → append the tick's decision + mental-trade log to the lessons file. Keep the equity curve vertical.

Glossary + what to watch for

A small dictionary for the words you met today. If a word feels fuzzy, come back here.

API
A way for one program to ask another program to do something.
API key
A permission token that lets a program act on your behalf without using your login password.
Balance
How much of something you have in an account.
Brokerage API
A Coinbase API path used for account, product, and order actions.
Cron
A repeating job or timer. In this tutorial, Hermes runs on a 10-minute loop.
Dashboard
The main control page for a program. Here, the Hermes dashboard in your browser.
Exchange
A place where you can buy, sell, or trade crypto.
Hermes
The AI trading helper you installed on your computer.
Leverage
Using borrowed buying power to open a larger position than your balance alone would allow.
Margin
The collateral or risked amount behind a leveraged position.
Model
The AI brain Hermes uses to think and respond.
Nous Portal
The place where you can get a Nous API key so Hermes can use a Nous model.
Perpetual futures
A type of futures contract that does not have a fixed expiry date.
Portfolio
The collection of assets and balances you hold.
Provider
The source of the model Hermes uses. This tutorial uses Nous.
TP / SL
Take-profit and stop-loss — the price levels where a trade may close in profit or to limit downside.
WebSocket
A live data connection some exchanges and programs use for streaming prices and updates.

What to watch for after setup

  • Refresh Hermes chats now and then. Fresh cron chats mean the loop is alive.
  • Keep the Coinbase portfolio and Advanced Trading tabs handy when you want to check what is happening.
  • If a screen ever looks like an error page instead of numbers, that usually means a connection or settings issue, not a reason to panic.
  • Take your time. The first trades, if any, are not a test you have to ace today.
