0. What you need before starting

  • A Windows PC
  • PowerShell / Windows Terminal
  • A Blofin account + API key file on your machine
  • VPN exit in a Blofin-accepted country (this guide assumes that)
  • Optional but recommended: free OpenRouter key at openrouter.ai/keys
You do not need Cursor for this tutorial. Install Hermes with PowerShell, then use Hermes chat/dashboard for everything after that.

1. Install Hermes (no AI)

  1. Open PowerShell.
  2. Copy/paste this install command and press Enter:
PowerShell — install Hermes 
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
  1. Close PowerShell, open a new PowerShell window.
  2. Confirm Hermes works:
PowerShell — verify 
hermes --version
hermes doctor

Optional guided setup:

PowerShell — setup wizard 
hermes setup

2. Open the Hermes dashboard

This is your control panel in the browser.

PowerShell — launch dashboard 
hermes dashboard

Browser should open automatically. If not, go here:

Dashboard URL 
http://127.0.0.1:9119
Leave this running. You will use the dashboard Cron tab and/or Hermes chat to create the 1-minute job.

3. Set free Nous + Tencent/Hy models

Goal: Hermes should use free models so cron ticks don’t burn paid credits.

A) Add OpenRouter key (recommended)

  1. Create a key at openrouter.ai/keys.
  2. Open this file in Notepad:
Env file path 
%LOCALAPPDATA%\hermes\.env
Add this line to .env 
OPENROUTER_API_KEY=sk-or-v1-YOUR_KEY_HERE

B) Choose the free model

PowerShell — model picker 
hermes model

Or put this in %LOCALAPPDATA%\hermes\config.yaml:

config.yaml — free Nous / Tencent Hy 
model:
  provider: nous
  base_url: https://inference-api.nousresearch.com/v1
  default: tencent/hy3:free
Free models rotate. If tencent/hy3:free stops working, run hermes model again and pick another live free model from OpenRouter free models (or another Nous free endpoint). Don’t hard-depend on one free ID forever.

If you use Nous Portal inference, also run:

PowerShell — Nous portal login 
hermes setup --portal

4. Put your Blofin API keys where Hermes can find them

Create a plain text file with your Blofin Passphrase, API Key, and API Secret. Put it somewhere stable on your PC, then update the path inside the cron prompt in Section 7.

Example credentials file contents 
Passphrase: YOUR_PASSPHRASE
API Key: YOUR_API_KEY
API Secret: YOUR_API_SECRET
Example path (change to yours) 
C:\Users\YOURNAME\Downloads\My Blofin API Compendium.txt
Never post your real keys in Discord/GitHub/chat. Only put the path in the cron prompt on your own machine.

5. Start the gateway (keeps cron alive)

Open a second PowerShell window and keep this running:

PowerShell — gateway 
hermes gateway
The gateway is what wakes cron jobs. If you close it, the 1-minute trading loop stops.

6. Create the 1-minute trading cron

Now Hermes is installed. From here, Hermes itself is the automation.

Option A — from Hermes chat (easiest)

  1. In a third PowerShell window, run hermes.
  2. Copy Section 7’s full prompt into a notepad file so you have it ready.
  3. In Hermes chat, paste:
Hermes chat — create cron 
/cron add "every 1m" "PASTE_THE_FULL_SECTION_7_PROMPT_HERE" --name "blofin-equity-vertical" --deliver local

Option B — from dashboard

  1. Open http://127.0.0.1:9119
  2. Go to the Cron tab
  3. Create job:
    • Schedule: every 1m
    • Name: blofin-equity-vertical
    • Prompt: paste Section 7
    • Deliver: local
  4. Save, then run once to test
Useful cron commands (in Hermes chat) 
/cron list
/cron run <job_id>
/cron pause <job_id>
/cron remove <job_id>
1-minute note: if one tick takes longer than 60 seconds, the next tick can be delayed. That is normal. Do not force more aggressiveness — forced entries lose money.

This is the prompt that makes Hermes trade like a persistent Blofin operator: manual decisions each tick, Camoufox / curl_cffi for WAF issues, isolated margin, longs and shorts, and durable learning at the start and end of every tick.

Before pasting: replace the credentials path with your real file path.

Full 1-minute Blofin cron prompt

--- HOW TO ACTUALLY GET TRADES THROUGH (THE “UNCONQUERABLE” BLOCKER) ---
What looks like a hard block is usually NOT “Blofin banned you” and NOT “API keys invalid.”

SYMPTOM
Private REST calls return HTML instead of JSON, often a Blofin page saying the IP is from a restricted country/region, or a Cloudflare challenge page. Signed clients then report: Failed to get server time, official SDK not available, empty account, placeOrder never reached. That is a transport / WAF / fingerprint problem, not a strategy problem.

WHY IT HAPPENS
1) Plain Python `requests` / default User-Agent hits Cloudflare or Blofin edge WAF and gets HTML.
2) Wrong base URL (demo vs live). Live must use https://openapi.blofin.com (and matching WS). Demo host is often CF-blocked from Python even when live works.
3) Wrong or stale credentials file loaded.
4) Broken/incompatible PyPI `blofin` package (missing methods, bad AccountAPI). Do not depend on that package as the only path.
5) Clock skew on signed requests — sync to Blofin server time when signing.
6) Missing ACCESS headers / passphrase / brokerId when the key requires them.

WHAT IS TRUE FOR THIS SETUP
- Operator VPN is already in a Blofin-accepted country (NL-compatible posture). Netherlands is not on Blofin’s restricted list for retail access; Dutch/EU users can register and trade. MiCA/offshore status is regulatory context, not a reason to invent geo-blocks.
- From an accepted-country IP, Blofin REST/WS normally work without “special” geo-unblocking IF the HTTP client looks like a real browser, not a bare bot fingerprint.
- Therefore: do NOT conclude “impossible.” Fix the client path until JSON comes back.

REQUIRED FIX ORDER (DO THIS BEFORE YOU CLAIM YOU CAN’T TRADE)
A) Verify VPN exit IP is still in an accepted country. If HTML geo page persists after A–D, rotate VPN exit once, then retry. Do not thrash.
B) Prefer Camoufox (browser) for any UI confirmation AND for establishing a real browser TLS/JA3 fingerprint when needed. Use Camoufox to open Blofin, confirm account/login/state if API is cloudy, and to manually place/verify orders when REST is fighting WAF.
C) For API: use curl_cffi (or equivalent) with Chrome impersonation — same idea as chrome110 / safari17 / chrome120 fingerprint rotation. Set Origin/Referer to blofin.com. Retry impersonation profiles on 403 HTML.
D) Confirm live endpoints and live credentials. Test in this order: public time → public tickers → signed balance → positions → one tiny isolated order with TP/SL only after balance reads as JSON.
E) If “Failed to get server time”: fix transport first (CF bypass), then re-sync timestamp. Do not keep retrying signed trade calls against HTML.
F) If package SDK is broken: call REST directly with correct ACCESS-KEY / ACCESS-SIGN / ACCESS-TIMESTAMP / ACCESS-PASSPHRASE (and broker id if required). Parse only JSON. If body starts with <!DOCTYPE html>, treat as transport failure and escalate A–C — never parse HTML as account data.
G) Never fall back to a fake demo $40 equity when live sync fails. Refuse phantom balances. Fix the pipe, then trade.

SUCCESS CRITERIA FOR “API WORKS”
- Account balance returns JSON with real USDT equity/available.
- Positions/orders endpoints return JSON.
- A manual order you place (via Camoufox UI or signed REST) shows up on Blofin.
Only after that do you scale activity.

--- TRADING RULES (MANUAL, AUTONOMOUS) ---
Scan the full USDT universe yourself (REST/WS/Camoufox — your eyes and judgment). Manually choose entries. Place orders yourself. Attach TP/SL yourself. Isolated margin only. Prefer clarity over activity. Compound wins; do not force rotations with thin free margin. Stay open to longs and shorts. No max position cap — but every position must have a clear edge and hard risk.
If something breaks mid-session: TROUBLESHOOT AND FIX ANY/ALL ISSUES THAT ARISE using the blocker playbook above. Do not stop at “blocked.” Fix transport, verify JSON, then resume trading.

PROCEED NOW
Confirm credentials path → confirm VPN accepted country → prove JSON account read (Camoufox and/or curl_cffi) → scan → take righteous trades by hand → manage positions → keep equity curve vertical.

LEARNING ACROSS CRON TICKS (WRITE BEFORE YOU FINISH)
After this cycle: write what worked, what failed, and the exact reusable rule into a durable skill or lessons file (Hermes skills/memory and/or a local lessons markdown/jsonl file).
Include: symbol/setup type, long or short, why taken or skipped, outcome if known, and the next-tick rule.
Next tick must be able to load and use those updated lessons with no chat history.
If nothing material changed, still append a one-line “hold / no edge” note with timestamp so the learning trail stays continuous.

8. Confirm it is actually trading / learning

  1. Run one tick now: /cron run <job_id>

  3. Watch Blofin for positions / TP-SL after a real entry.
  4. Confirm lesson files grow under %LOCALAPPDATA%\hermes\.

Get-ChildItem "$env:LOCALAPPDATA\hermes\cron" -ErrorAction SilentlyContinue
